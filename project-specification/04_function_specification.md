## Feature 1 — Resident login & email two-factor authentication

- **Purpose:** Let an apartment resident securely log in and verify their identity with a one-time email code.
- **Who uses it:** Residents (`UserKbn = 4`).
- **Business rules:**
  - Credentials checked against `tUserM` by `editBukkenCD` + room number (`ID`) + password (`Passwd` or `Passwd2`), with `MukouFlg = FALSE` and `UserKbn = '4'`.
  - If `editBuildingCD` is supplied, the block must also match.
  - If email is not yet verified (`EmailVerified = 0`) the resident is sent to register/verify an email first.
  - If verified, a 6-digit code (`random_int(0,999999)`, zero-padded) is generated with a **30-minute** expiry and emailed; the user must enter it.
  - On success a fresh `RegistKey` is issued and stored with `LastLogin`/`LastLoginIP`.
- **Input:** `editBukkenCD`, `wID`, `wPasswd`, `editBuildingCD`, `verificationCode`.
- **Output:** redirect to `top.php?rKey=…`; or the 2FA entry page; or an error message.
- **Validation:** required fields; code correctness and expiry.
- **Related screens:** `login.php` (`login.tpl`), `login_2fa.tpl`, `mail_regist.php`.
- **Related APIs:** none (form posts).
- **Related DB tables:** `tUserM`.
- **Related jobs:** none.
- **Related events:** sets `EmailVerificationCode`, `EmailVerificationExpiry`, `RegistKey`, `LastLogin`, `LastLoginIP`.
- **Related notifications:** 2FA email via `sendTwoFactorAuthMail()` (`httpdocs/include/common_489.php`).
- **Code:** `httpdocs/login.php`, `httpdocs/login_finish.php`.

## Feature 2 — Staff / contractor login

- **Purpose:** Log in NESPE office staff and inspection contractors.
- **Who uses it:** `UserKbn = 1/2/3`.
- **Business rules:** authenticate against `tUserM` where `UserKbn <> '4'`. IDs containing `nespe`, or users with `Skip2faFlg = 1`, **skip** the email code; everyone else does the same 6-digit email 2FA as residents. Success → `s_search.php` (`&m=1` for mobile).
- **Input:** `wID`, `wPasswd`, `verificationCode`, `m`.
- **Output:** redirect to `s_search.php?rKey=…`.
- **Validation:** required `wID`/`wPasswd`; code correctness/expiry.
- **Related screens:** `login_form.php` (`login_form.tpl`), `login_2fa.tpl`.
- **Related DB tables:** `tUserM`.
- **Related notifications:** 2FA email.
- **Code:** `httpdocs/login_form.php`, `httpdocs/login_finish2.php`.

## Feature 3 — Session management (rKey)

- **Purpose:** Identify the logged-in user across every page.
- **Who uses it:** all logged-in users.
- **Business rules:** `User::doAuthenticationByRegistKey($rKey)` looks up the row by `RegistKey` (active, not withdrawn). An **idle timeout of 360 minutes** (`$Timeout`, set in `SPFW/inc/global.inc`) rotates the key and forces re-login by setting `UserCD = -1`. The `rKey` is carried in every URL/query string.
- **Input:** `rKey` (GET/POST).
- **Output:** an authenticated `User` object, or a redirect to login.
- **Related DB tables:** `tUserM`.
- **Code:** `SPFW/class/SPUSUser.cls` (`doAuthenticationByRegistKey`, `getNewKey`).

## Feature 4 — Property (Bukken) registration & maintenance

- **Purpose:** Define a building project: units, floors, blocks, dates, assigned contractor and staff.
- **Who uses it:** NESPE staff (`UserKbn 1/2`).
- **Business rules:** stored in `tBukkenM`; blocks (棟) stored in `tBuildingM` when `TatoFlg` (multi-block); inspection-schedule rows in `tKojiNitteiF`; no-work days (`Holiday1`) and reserve days (`ReserveDay`) stored pipe-encoded (`|a|b|`). New `BukkenCD` is generated by lock-table + max+1 (no AUTO_INCREMENT). Address geocoded via Google Maps at first registration.
- **Input:** the full basic-info field set (see screen 2.4).
- **Output:** saved property; redirect to `s_menu.php`.
- **Validation:** required name; numeric unit/floor counts (normalized with `mb_convert_kana`).
- **Related screens:** `s_form_sinki.php`/`s_finish_sinki.php` (new), `s_kihon_form.php`/`s_kihon_finish.php` (edit), `s_kihon_copy.php` (copy).
- **Related DB tables:** `tBukkenM`, `tBuildingM`, `tKojiNitteiF`, `tGyosyaM`, `tKanriCompanyM`, `tBrancheM`.
- **External:** Google Maps Geocoding API.
- **Code:** `httpdocs/s_kihon_finish.php`, `httpdocs/s_finish_sinki.php`.

## Feature 5 — Work-schedule / slot-grid configuration

- **Purpose:** Configure the teams, slot pattern, no-work/reserve days and room matrix that produce the booking grid.
- **Who uses it:** NESPE staff / contractors.
- **Business rules:**
  - `Hansu` = number of crews/班 working in parallel; `WakuPattern` chooses the AM/PM time-slot layout (defined in `$WAKUPATTERN`, `SPFW/inc/489.properties`); `MaxWakuSu` = max slots per period (pipe-encoded like `10-10`).
  - `FirstDateFeature` controls first-day restrictions (1 = AM not usable; 2 = unusable until 15:00).
  - `FrameOverflow` allows overflow beyond a slot ("枠越").
  - `ArrangeType` = 1 for inspection (点検) vs 0 for construction (工事).
  - The room layout (floor × room) is stored in `tBukkenMatrixM.KaiRoom` (pipe-encoded). `FloorReserveInfo` stores per-floor day/AM-PM/column-count as JSON.
  - The system computes recommended slot counts and warns if units won't fit.
- **Input:** `Hansu`, `WakuPattern`, `MaxWakuSu`, `Holiday1`, `ReserveDay`, `FirstDateFeature`, `ArrangeType`, `KaiRoom`, `FloorReserveInfo`.
- **Output:** configured property; downstream grid (`tReservationInitF`/`tReservationF`).
- **Related screens:** `doc/s_make_kanryo2.php`, then `s_format.php`.
- **Related DB tables:** `tBukkenM`, `tBuildingM`, `tBukkenMatrixM`, `tReservationF` (delete on `work=2`), `tReservationInitF`.
- **Code:** `httpdocs/doc/s_make_kanryo2.php`.

## Feature 6 — Resident reservation booking ("kakutei" single-slot flow)

- **Purpose:** Let a resident book one date + one time slot for their unit's inspection.
- **Who uses it:** Residents.
- **Business rules:**
  - Slot availability computed from `WakuPattern`, `MaxWakuSu`, `Hansu`, holidays (`tCalendarF`, `Holiday1`), and existing bookings (`tReservationF`), via page functions `getAkiWaku()`, `getAkiWakuTime()`, `getAkiWakuAMPMTime()`.
  - Calendar cells show ○ available / △ few left / × full / 休 no-work day.
  - On finish, a real open slot is resolved; if none, an error is shown.
  - The booking writes `tReservationF` with `Status=1`, date/time, `MenuCD`, `StylistCD`, `UserMemo`, and computes `HanNo` (team/lane) from capacity.
  - `flag` semantics: 1=confirm new, 2=change, 3=decline. `ReplyFlg`/`ConfirmFlg` on `tUserM` track the resident's answer.
  - A `$_SESSION['ticket']` guards against double submission.
- **Input:** `wDate`, `wTime`, `wUserMemo`, `flag`.
- **Output:** saved reservation; confirmation email; redirect to `top.php`.
- **Validation:** must pick a slot (`日程を選択してください。`); must have name/phone first.
- **Related screens:** `reserve_form_kakutei.php` → `reserve_confirm_kakutei.php` → `reserve_finish_kakutei.php`; `reserve_list.php`; `kakutei.php`.
- **Related DB tables:** `tReservationF`, `tUserM`, `tBukkenM`, `tBuildingM`, `tMenuM`, `tStylistM`, `tClientM`, `tBrancheM`, `tBukkenWebActivityF`.
- **Related events:** `recordBukkenWebActivity()` (lights the staff bell).
- **Related notifications:** confirmation/change/decline email (`mb_send_mail`).
- **Code:** `httpdocs/reserve_finish_kakutei.php`.

## Feature 7 — Telephone reception (staff books on behalf of resident)

- **Purpose:** When a resident phones the office, staff register/confirm/change/decline/restore their slot.
- **Who uses it:** NESPE staff.
- **Business rules:** `work` action 1=register info, 2=confirm, 3=change, 4=decline, 5=restore. Uses the same slot engine as `s_format`. Sets `tUserM.ReplyFlg=2` (TEL受付) and `ConfirmFlg` as appropriate.
- **Input:** `HenkoDate`, `TimeFromTime`, `HanNo`, `ViewOrderNo`, `RoomNo`, `Name`, `TEL`, `EMail`, `Memo`, etc.
- **Output:** updated reservation grid.
- **Related screens:** `sh_list.php`.
- **Related DB tables:** `tReservationF`, `tUserM`, `tBukkenM`, `tReservationInitF`.
- **Code:** `httpdocs/sh_list.php` (+ helpers `httpdocs/include/sh_list_slot_helpers.php`).

## Feature 8 — Resident notice generation (Excel + QR)

- **Purpose:** Produce the printable notice given/posted to residents, including the slot grid and a QR code to the booking site.
- **Who uses it:** NESPE staff / contractors.
- **Business rules:** `s_format.php` previews the grid from `tReservationInitF`. `s_format_Excel.php` selects one of 25 templates (`template/temp01–25.xlsx`) based on entry mode (partial/whole-building) × inspection-day count × half/full-day, fills company/contact/room/time cells, embeds the QR, and downloads `お知らせ_<name>_<datetime>.xlsx`. Fire-prevention uses `s_haifu_bousai_Excel.php` with a per-property template.
- **Input:** `editBukkenCD`, `TenkenKind` (1=機器/2=総合), format type.
- **Output:** `.xlsx` download.
- **Related DB tables:** `tBukkenM`, `tUserM`, `tClientM`, `tKanriCompanyM`, `tKojiNitteiF`, `tUploadFileF`, `tReservationInitF`.
- **External:** Endroid QR code library.
- **Code:** `httpdocs/s_format.php`, `httpdocs/s_format_Excel.php`, `httpdocs/s_haifu_bousai_Excel.php`.

## Feature 9 — Inspection completion & digital signature

- **Purpose:** Record that each unit's inspection was completed, with the resident's signature.
- **Who uses it:** Inspection crew (on a device) + staff.
- **Business rules:** the resident/crew signs on `s_sign.php`; `s_sign_regist.php` saves the PNG→JPG under `upfile/…`, inserts `tSignF`, and sets the matching `tReservationF.KanryoFlg = 1`. The completion report (`s_kanryo_download.php`) embeds the signatures into `complete_report.xlsx`.
- **Input:** base64 image (`imgData`), `wID`, `editBukkenCD`, `editBuildingCD`.
- **Output:** saved signature file + DB row; completed reservation; Excel report.
- **Related screens:** `s_sign.php`, `s_kanryo.php`, `s_kanryo_download.php`.
- **Related DB tables:** `tSignF`, `tReservationF`, `tBukkenM`, `tBuildingM`, `tUserM`.
- **Code:** `httpdocs/s_sign_regist.php`, `httpdocs/s_kanryo.php`.

## Feature 11 — Request-to-contractor & reminder emails (batch)

- **Purpose:** Ask contractors to register inspection dates, then chase them and escalate.
- **Who uses it:** the system, on a schedule (no human screen).
- **Business rules:** target = inspection in +2 months. The initial request **resets** `KikiStatus=1` (or `BousaiStatus=1`) and invalidates old reports. Reminders re-email contractors who are still at status 0/1; escalations email internal staff after ~16–20 days; day-before reminders fire when `Date1`/`BousaiStartDate` = tomorrow.
- **Input:** none (date math).
- **Output:** emails; status resets on the initial request.
- **Related DB tables:** `tBukkenM`, `tGyosyaM`, `tUserM`, `tResidentsFormF`, `tResultReportF`.
- **Related jobs:** see **10_batch_jobs.md**.
- **Related notifications:** see **08_notification_specification.md**.
- **Code:** `httpdocs/s_MailIraiToSeko*.php`, `httpdocs/s_Mail_Tenken_Yesterday*.php`, single web trigger `httpdocs/IraiToSekoCompany.php`.

## Feature 12 — Staff "bell" web-activity alerts

- **Purpose:** Notify staff in the console header when residents book/update reservations.
- **Who uses it:** staff (`UserKbn 1/2/3`); residents excluded.
- **Business rules:** resident booking calls `recordBukkenWebActivity()` → upsert `tBukkenWebActivityF` (type 1=予約, 2=更新). The header bell polls for unread items scoped by role (`ClientCD`/`BrancheCD`/`GyosyaCD`); read-state in `tBukkenAlertReadF`.
- **Input:** `rKey`, `editBukkenCD`, `markAll`.
- **Output:** JSON `{count, items}`; `{ok}`.
- **Related screens:** the staff header (all `s_*` pages); driven by `js/bukken_alert.js`.
- **Related APIs:** `get_bukken_alerts.php`, `mark_bukken_alert_read.php`.
- **Related DB tables:** `tBukkenWebActivityF`, `tBukkenAlertReadF`, `tBukkenM`.
- **Code:** `httpdocs/include/bukken_alert.php`.

## Feature 15 — Document / Excel generation suite

- **Purpose:** Produce all the operational paperwork (schedules, notices, device-setting sheets, completion/inspection reports, contracts, estimates).
- **Who uses it:** staff / contractors.
- **Business rules:** scripts under `httpdocs/doc/` load an `.xlsx`/`.docx` template from `httpdocs/template/`, fill it from the DB using PhpSpreadsheet/PHPExcel, save to `tmp/`, optionally register in `tFileF`, and stream it.
- **Related DB tables:** `tBukkenM`, `tReservationF`/`tReservationInitF`, `tKojiNitteiF`, `tFileF`, `tSignF`, `tResultReportF`.
- **Code:** `httpdocs/doc/*.php`, templates in `httpdocs/template/`.

## Feature 16 — Multilingual labels

- **Purpose:** Show UI labels in the chosen language.
- **Business rules:** `get_lang()` (currently pinned to `ja`) + `get_word($myDB)` load label strings from `tWordM` (columns `ja/en/zh/es/ko`), resolved per label by `set_word()` with Japanese fallback. A handful of customer screens have `_eng.tpl` layout variants.
- **Related DB tables:** `tWordM`.
- **Code:** `httpdocs/include/common_489.php`.
